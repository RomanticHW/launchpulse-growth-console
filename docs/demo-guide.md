# 功能体验指南

本指南用于体验 LaunchPulse 的主要操作流程。开始前请先完成数据库准备并启动应用。

```bash
bundle config set --local path vendor/bundle
bundle install
bin/rails db:prepare
bin/rails db:seed
bin/dev
```

登录账号：

```text
demo@launchpulse.test / password
```

## 1. 查看站点

登录后打开 `clearleaf-skincare` 或其他示例站点。站点详情页包含以下区域：

- 页面结构与历史版本；
- 当前草稿的页面预览；
- 全站访问与转化数据；
- 页面优化建议；
- A/B 实验；
- 最近访客事件。

公开预览使用最新发布版本，后台预览使用当前草稿。两者内容可能不同，这是正常的发布隔离行为。

## 2. 分析页面

点击 `分析页面`。系统会根据区块类型和当前内容生成结构化建议，每条建议包含：

- 关联区块；
- 当前问题；
- 调整依据；
- 建议修改的字段；
- 重点观察指标；
- 参考置信度。

当前分析使用固定规则，不依赖外部服务，因此每次初始化后的结果保持稳定。

## 3. 预览并应用改动

打开一条建议并点击 `预览改动`，页面预览会临时展示调整后的内容。预览不会写入数据库。

确认后点击 `应用到草稿`。该操作只更新后台草稿，不会立即改变公开站点。需要撤销时，可以在同一条建议中点击 `撤回`。

## 4. 创建对照实验

点击 `创建对照实验`。系统会保存两个版本：

- 原始版本：建议应用前的区块内容；
- 优化版本：建议应用后的区块内容。

两个版本都保存完整区块数据。实验开始后，即使后台继续编辑或发布页面，实验内容也不会随之变化。

同一区块一次只能有一个尚未处理完的实验。

## 5. 产生访客事件

点击 `公开预览`，然后根据站点内容执行以下任一操作：

- 提交联系或资料领取表单；
- 点击商品购买按钮；
- 选择课程方案。

这些操作会创建真实的示例业务记录和访客事件。页面浏览、按钮点击等轻量操作也会进入事件流。

如需查看访客编号和实验版本，可以使用调试模式启动：

```bash
DEMO_DEBUG=true bin/dev
```

## 6. 查看数据

返回站点详情页，可以看到事件流、页面浏览、独立访客、转化率、来源、设备和实验数据更新。

数据先由后台任务聚合，再通过实时通道更新页面。如果页面没有立即变化，请确认 `bin/dev` 中的 Web、CSS 和任务进程都在运行。

需要快速补充分析数据时，可以在 `测试工具` 中点击 `模拟 1000 位访客`。模拟任务不会批量创建联系人、表单提交或订单。

## 7. 结束实验并选择版本

实验有足够数据后，点击 `结束实验`。结束后选择采用原始版本或优化版本。

该操作会把所选版本写入当前草稿，并记录实验结果。公开站点仍不会改变，直到再次发布。

## 8. 发布和恢复版本

点击 `发布` 生成新的已发布版本。随后可以在版本记录中：

- 查看该版本与当前草稿的内容差异；
- 查看完整版本数据；
- 将历史内容恢复为一个新的发布版本。

如果站点仍有未处理完的实验，系统会阻止恢复操作，避免页面内容与实验状态不一致。

## 常见问题

### 页面没有样式

```bash
bin/rails tailwindcss:build
```

### 实验按钮不可用

检查该建议或区块是否已有进行中的实验，或者是否已有实验结果尚未应用。

### 实时数据不更新

确认 Solid Queue 任务进程与 Web 进程正在运行，并且两者连接到同一套 Solid Cable 数据库。

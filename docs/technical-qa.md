# 技术问答

## 为什么公开站点不直接读取当前区块？

后台区块代表草稿，运营人员可能正在编辑或预览。公开站点只读取最新 `PublishedSnapshot`，确保未发布内容不会提前展示。

## 发布版本保存哪些内容？

版本记录包含站点信息、页面、区块顺序、区块类型、稳定 `uid`、属性、版本号、发布时间和校验和。公开渲染、内容差异和历史恢复共用这份数据。

## 校验和用于什么？

恢复历史版本前，系统会重新计算内容校验和。如果历史数据被修改或损坏，恢复操作会被拒绝。

新版本使用规范化 JSON 计算 SHA256，避免哈希键顺序影响结果。早期本地版本仍保留兼容校验。

## 为什么区块需要 `uid`？

数据库编号只适合当前数据库内部引用。区块经过导入、删除重建或历史恢复后，数据库编号可能变化。

`Section.uid` 是长期业务标识，用于发布版本、公开事件、实验、归因和恢复。

## `SectionPatch` 为什么保存修改前后内容？

补丁需要支持预览、应用、撤回和实验。保存 `before_props` 与 `after_props` 后，实验可以固定使用创建时的两个版本，不受后续页面编辑影响。

## 原始实验版本从哪里获得？

创建实验时优先使用 `patch.before_props`；没有补丁时才使用当前 `section.props`。优化版本优先使用 `patch.after_props`。

两个版本都保存完整区块属性，不在运行时重新读取当前发布内容。

## 为什么同一区块不能同时运行多个实验？

公开页面根据 `section_uid` 选择实验版本。如果同一区块存在多个未处理完的实验，渲染和转化归因都会出现歧义。

创建实验时，`Experiments::LifecycleService` 会锁定区块并检查现有状态。

## 访客为什么不会每次随机分配版本？

`AssignmentService` 根据实验编号和访客编号计算稳定结果，再按版本权重分桶。首次分配后会保存 `Assignment`，后续访问直接复用。

## 实验结束后为什么还要选择版本？

结束实验只停止新的分配和数据写入，不代表系统已经做出内容决策。运营人员仍需选择采用原始版本或优化版本。

所选内容写入草稿后，还要单独发布才会出现在公开站点。

## 转化归因的优先级是什么？

1. 显式实验与版本；
2. 页面区块；
3. 通用转化。

显式归因只记录指定实验。区块归因只记录该区块的实验。缺少实验和区块信息时，才使用访客已有分配和实验目标进行通用匹配。

## 为什么一次转化不能计入访客参加的所有实验？

访客可能同时看到多个实验区块，但最终转化通常发生在其中一个具体区块。将一次订单计入所有实验会放大结果并破坏实验含义。

## 公开事件会检查什么？

公开事件会检查事件类型、来源、设备、元数据和区块可见性。带 `section_uid` 的事件必须来自最新发布版本中的区块。

表单提交和订单创建不能通过普通公开埋点接口直接上报，必须使用相应的受控业务入口。

## Events API 为什么使用签名站点令牌？

Events API 是开放入口，需要确认事件属于哪个站点，同时避免调用方直接提交数据库编号。

站点令牌由 Rails `MessageVerifier` 签名，并与有效 `ApiKey` 的摘要匹配。令牌可以轮换和停用。

## 为什么幂等键还需要请求指纹？

调用方可能错误复用同一个幂等键，但事件内容已经变化。只比较幂等键会导致新事件被当作旧事件返回。

请求指纹包含事件类型、访客、来源、设备、页面、区块、实验、时间和清洗后的元数据。

- 同键同内容：返回已有事件；
- 同键不同内容：拒绝请求。

## 为什么幂等处理使用 PostgreSQL advisory lock？

并发请求可能同时使用相同幂等键。事务级 advisory lock 可以让同一站点和幂等键的检查按顺序执行。

系统先检查已有事件和请求指纹，再创建实验分配与事件，避免被拒绝的请求留下多余数据。

Solid Queue 负责后台事件聚合和访客模拟任务。公开页或事件接口创建 `Event` 后，统一 dispatcher 会先领取数据库租约，再入队 `AggregateEventJob`。聚合任务更新 rollup、转化记录和 `aggregated_at`；production 另有每 5 分钟运行的恢复任务，重新领取遗漏或租约过期的未聚合事件。这样请求路径不用同步完成所有统计，也避免普通幂等重放反复制造队列项。

production 只提供一个 `DATABASE_URL` 时，系统会从主库名派生独立的 cache、queue、cable 数据库，避免四套 schema 共用 `schema_migrations` 后跳过初始化。`db:prepare` 需要数据库角色具备 `CREATEDB`，或者部署平台已预先创建四个数据库；专用 URL 覆盖也必须指向可独立迁移的数据库。

## 元数据有哪些限制？

`metadata` 顶层必须是对象，内部可以包含数组和嵌套对象。清洗器限制总大小、深度和每层键数量，并把 Rails 参数对象转换为普通哈希。

## 表单和订单如何保持事务一致？

公开表单会在事务中创建联系人、提交记录和事件。商品或课程方案操作会在事务中创建订单和事件。

事件写入失败时，相应业务记录会回滚，避免看板出现订单与转化数据不一致。

## `checkout_click` 为什么不是主要转化？

点击购买只表示操作意向，`order_created` 才表示订单已经创建。商品和课程方案统一使用订单创建作为主要转化指标。

## Solid Queue 和 Solid Cable 分别负责什么？

Solid Queue 处理事件聚合、访客模拟和延迟看板刷新。Solid Cable 将任务完成后的事件、指标和实验结果推送到后台页面。

## 历史恢复会回退整个数据库吗？

不会。系统只恢复指定版本中的页面和区块到当前草稿，再发布为一个新版本。其他业务数据不会回退。

## 当前版本距离生产环境还有哪些差距？

主要包括真实支付、完整团队权限、严格实验统计、批量事件采集、可靠消息机制、多页面公开站点、监控告警和备份恢复。详细内容见[当前限制与后续规划](../readme/08-limitations-and-roadmap.md)。

# 公开站点与事件接口

公开站点负责渲染已发布页面并采集访客行为。Events API 为外部页面或其他系统提供相同的事件写入能力。

## 公开路由

```text
GET  /s/:slug
POST /s/:slug/events
POST /s/:slug/forms/:form_id/submissions
POST /s/:slug/products/:product_key/checkout
POST /s/:slug/plans/:plan_key/checkout
```

当前公开运行时只开放首页。数据模型保留了页面路径，多页面支持需要进一步按路径校验可见区块。

## 页面渲染

公开页面读取最新 `PublishedSnapshot`，不读取后台草稿。

渲染每个区块时：

1. 没有实验分配的访客看到已发布版本；
2. 已分配实验的访客看到该实验版本保存的完整区块内容。

原始版本同样读取实验创建时保存的数据，不会随之后的页面发布发生变化。

## 访客与会话

公开页面使用签名 Cookie 保存访客编号和会话编号。访客编号用于稳定实验分流，会话编号用于关联同一次访问中的事件。

生产环境 Cookie 使用 `secure` 属性。普通请求参数不能覆盖签名访客编号。

## 表单提交

表单字段根据后台配置渲染。字段 `key` 用于提交和历史数据，展示名称可以独立修改。

提交成功后创建：

- 联系人；
- 表单提交记录；
- `form_submit` 事件；
- 事件聚合任务。

邮箱格式错误、必填字段缺失或表单区块未发布时，请求返回 422，并且不会保存业务记录。

## 示例订单

商品和课程方案操作会创建示例订单，不调用支付平台。

商品订单同时创建 `checkout_click` 和 `order_created` 事件。订单与事件位于同一事务中，事件写入失败时订单也会回滚。

商品购买必须来自包含该商品的已发布商品区块，课程方案必须来自已发布价格区块。仅传入商品或方案参数不能绕过区块校验。

## 公开事件采集

页面按钮、商品和表单会尽量附带 `section_uid`。后端会确认该区块仍存在于最新发布版本中，草稿区块和已移除区块不能继续产生实验数据。

表单提交和订单创建不能通过普通公开埋点接口直接伪造，必须使用对应的受控业务入口。

## Events API

```text
POST /api/v1/events
```

示例请求：

```json
{
  "site_token": "signed-token",
  "event_type": "page_view",
  "visitor_id": "visitor-123",
  "session_id": "session-123",
  "source": "search",
  "device": "mobile",
  "section_uid": "section-uuid",
  "idempotency_key": "event-123",
  "metadata": {
    "campaign": "summer"
  }
}
```

处理步骤：

1. 验证站点令牌；
2. 校验事件类型、来源和设备；
3. 清洗元数据；
4. 检查区块是否已发布；
5. 检查显式实验和版本；
6. 处理幂等键与请求指纹；
7. 创建事件和必要的实验分配；
8. 提交后台聚合任务。

完整字段和错误码见 [Events API](../docs/api-events.md)。

## 常见错误

- 站点令牌无效或已停用；
- 事件类型、来源或设备不支持；
- 元数据过大、过深或顶层不是对象；
- 区块不在已发布页面中；
- 实验与版本不匹配；
- 幂等键对应的请求内容发生变化；
- 请求频率超过限制。

Events API 使用结构化 JSON 返回错误；公开表单和订单入口使用可直接展示的中文提示。

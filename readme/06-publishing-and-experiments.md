# 发布与实验管理

发布系统负责隔离后台草稿与公开内容，实验系统负责固定比较版本并记录访客分配。两者共同使用页面区块的稳定标识。

## 草稿与公开版本

后台编辑 `Section` 草稿，公开站点读取最新 `PublishedSnapshot`。

```text
修改草稿 -> 预览 -> 发布 -> 生成版本记录 -> 公开站点读取新版本
```

未执行发布时，公开站点不会看到后台修改。

## 发布版本

每个版本记录包含：

- 站点信息；
- 页面与区块顺序；
- 区块类型、`uid` 和属性；
- 版本号；
- 发布时间；
- 内容校验和。

发布操作在站点锁内生成连续版本号，避免并发发布产生重复版本。

## 内容校验

发布内容会规范化为稳定 JSON，再计算 SHA256 校验和。恢复历史版本前会重新计算并比对，校验失败时停止恢复。

当前实现仍兼容早期本地版本使用的旧校验方式，新发布内容统一使用规范化校验和。

## 版本差异

差异页面展示：

- 新增区块；
- 删除区块；
- 修改区块；
- 字段修改前后的内容；
- 未发生变化的区块数量。

完整结构化数据可以通过 JSON 格式查看。

## 历史恢复

恢复操作不会把数据库整体回退到过去。系统会：

1. 校验历史版本内容；
2. 按 `Section.uid` 恢复页面区块到当前草稿；
3. 删除历史版本中不存在的草稿区块；
4. 将恢复后的内容发布为新版本。

因此版本历史保持连续，恢复操作本身也有新的版本号。

站点存在未处理完的实验时，系统会阻止恢复，避免实验内容与公开版本不一致。

## 实验创建

实验通常由一条优化建议和对应的 `SectionPatch` 创建。系统保存：

- 原始版本完整区块内容；
- 优化版本完整区块内容；
- 主要转化目标；
- 版本流量权重；
- 实验状态；
- 关联区块。

商品和价格区通常以 `order_created` 为目标，表单区通常以 `form_submit` 为目标。

## 访客分流

`Experiments::AssignmentService` 根据实验编号、访客编号和版本权重计算分配结果。首次分配会写入 `Assignment`，后续访问直接复用。

同一区块一次只能有一个尚未处理完的实验，避免公开页面出现多个相互冲突的版本。

## 实验状态

实验支持以下操作：

- 创建并运行；
- 暂停；
- 继续；
- 结束；
- 采用某个实验版本。

结束实验只停止新的分配和数据写入，不会自动修改页面。运营人员需要明确选择采用原始版本或优化版本。

## 实验结果

结果面板显示：

- 访客数；
- 转化数；
- 转化率；
- 相比原始版本的百分点变化；
- 相对提升；
- 近似置信度。

当前统计用于观察趋势，不提供严格的样本量决策、延迟转化窗口或多实验校正。

## 应用实验结果

采用实验版本时，系统会更新当前草稿、记录所选版本，并同步建议与补丁状态。补丁保存的修改前后内容不会被重写。

草稿更新后仍需单独发布，公开站点才会使用所选版本。

# 产品概览

LaunchPulse 用于管理网站发布后的页面优化工作。运营人员可以查看页面数据、定位需要调整的区块、创建 A/B 实验，并把确认后的内容发布到公开站点。

## 适用场景

项目内置三个示例站点：

- 社区咖啡店：提前点单、团队预订和表单咨询；
- 在线实战课程：课程介绍、资料领取和方案选择；
- 基础护肤品牌：商品展示、购买操作和常见问题。

这些站点共用同一套后台能力，但保留各自的页面结构、内容和转化目标。

## 主要能力

### 页面与版本

- 页面由首屏、卖点、表单、商品、价格、评价和问答等区块组成；
- 后台编辑草稿，公开站点读取已发布版本；
- 每次发布都会生成可对比、可恢复的版本记录；
- 区块使用稳定标识，发布和恢复不依赖数据库编号保持不变。

### 页面优化

- 根据区块类型和当前内容生成结构化建议；
- 展示建议原因、修改字段、观察指标和参考置信度；
- 支持预览、应用、撤回和忽略；
- 修改前后的内容会随补丁保存。

### A/B 实验

- 从优化建议创建原始版本和优化版本；
- 同一访客在实验期间保持相同版本；
- 访客事件按区块和实验版本归因；
- 实验结束后可以采用任一版本，再发布到公开站点。

### 数据与实时更新

- 采集页面浏览、按钮点击、表单提交和订单等事件；
- 后台任务聚合页面、来源、设备和漏斗数据；
- 实时通道将最新事件和指标推送到站点详情页；
- Events API 支持外部页面或系统上报事件。

## 操作流程

```text
查看站点数据
-> 分析页面
-> 预览并应用优化建议
-> 创建对照实验
-> 采集访客事件
-> 结束实验并选择版本
-> 发布或恢复历史版本
```

公开站点和后台草稿相互隔离。应用建议只会修改草稿；只有执行发布后，访客页面才会使用新内容。

## 示例数据

种子数据会创建一个示例账号、三个站点、公开页面、表单、商品、发布版本和基础访客事件。所有品牌名称、用户反馈和订单均为虚构内容，仅用于展示产品流程。

模拟访问功能只生成分析事件，不会批量创建联系人或订单。通过公开页面实际提交表单或选择商品时，系统会创建对应的示例业务记录。

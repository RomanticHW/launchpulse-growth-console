# 当前限制与后续规划

LaunchPulse 当前是一套可运行的产品原型，覆盖页面优化、实验、事件、分析和发布流程。以下能力尚未达到生产环境要求。

## 当前限制

### 页面分析

页面分析由固定规则生成，不调用外部模型服务。规则输出稳定，但无法理解任意行业、品牌语气和复杂页面上下文。

后续接入外部服务时需要补充：

- 输入与输出结构校验；
- 规则和提示版本管理；
- 超时、重试和降级；
- 调用成本与用量记录；
- 建议去重和人工编辑；
- 固定规则兜底。

### 支付与订单

商品和课程方案只创建示例订单，不接支付平台。生产版本需要增加：

- 支付下单和回调；
- 回调幂等；
- 订单状态；
- 退款与取消；
- 币种、税费和优惠；
- 异常支付处理。

### 实验统计

当前结果提供访客数、转化数、转化率、提升幅度和近似置信度，只适合观察趋势。

完整实验平台还需要：

- 独立曝光事件；
- 样本量和停止规则；
- 延迟转化窗口；
- 访客身份合并；
- 人群分层；
- 多实验互斥；
- 逐步放量；
- 严格统计检验。

### 权限与协作

当前提供 `owner`、`marketer` 和 `viewer` 三类角色，但没有成员邀请、账号切换、资源级权限和完整操作审计。

生产版本需要增加：

- 团队与成员管理；
- 资源级授权；
- 敏感操作二次确认；
- 接口密钥治理；
- 操作日志检索；
- 会话安全策略。

### 事件采集

Events API 以单条写入为主。公开表单和订单会先在事务中写入业务记录与事件，再提交聚合任务。

当前实现不是完整的事务消息方案。生产版本需要补充：

- 批量上报和请求压缩；
- 网关/边缘限流（当前已有 Rack::Attack 应用层基础限流；连接同一 cache DB 的实例共享限流状态）；
- 采样、流量控制和队列削峰；
- 可靠消息表；
- 自动补偿和死信处理；
- 事件版本；
- 数据仓库同步；
- 共享存储高可用与容量治理；
- 租户级配额、监控和告警。

公开表单和结账会先把业务记录与 `Event` 写入同一个事务，再由统一 dispatcher 领取 10 分钟派发租约并入队聚合任务。入队立即失败时会释放租约，幂等重放可马上补队；进程若在领取后退出，租约到期后也可重新领取。production 的 Solid Queue 每 5 分钟运行一次恢复任务，每批最多扫描 500 条按可信 `created_at` 判断至少已存在 2 分钟、尚未聚合且租约可用的事件，单条失败不会中断后续恢复。

仍可使用手工应急命令：

```bash
bin/rails launch_pulse:enqueue_unaggregated_events
```

命令会通过同一 dispatcher 领取并派发当前可用事件，并输出 enqueued / skipped / failed 数量。自动扫描和手工命令都复用同一数据库条件 claim，因此普通幂等重放或并发扫描不会持续放大队列项。

这仍不是事务 outbox：事件提交、租约领取和队列写入不是同一个原子事务。当前实现用失败释放、10 分钟租约和 5 分钟周期扫描覆盖崩溃窗口；更高可靠性部署仍应评估事务 outbox、队列监控和告警。

### 公开站点

当前公开运行时只开放首页 `/s/:slug`。多页面支持需要按页面路径扩展区块可见性、实验和事件校验。

站点内容来自种子数据，不提供页面导入、拖拽编辑、素材管理、自定义域名和移动端断点配置。

## 后续规划

### 第一阶段：站点接入

- 从 URL 导入基础页面内容；
- 将页面内容转换为结构化区块；
- 提供区块编辑和排序；
- 增加图片与素材管理；
- 支持多页面和移动端预览。

### 第二阶段：页面分析

- 接入外部分析服务；
- 支持品牌语气和行业上下文；
- 增加建议编辑与审批；
- 记录分析配置版本和调用成本；
- 保留固定规则作为降级方案。

### 第三阶段：实验平台

- 独立曝光事件；
- 自定义流量比例；
- 人群定向；
- 定时开始与结束；
- 多实验互斥；
- 守护指标和决策记录。

### 第四阶段：分析看板

- 日期范围和对比周期；
- 渠道、设备和浏览器下钻；
- 可配置漏斗；
- 访客分群；
- 数据导出；
- 异常检测。

### 第五阶段：发布协作

- 发布审批；
- 临时预览链接；
- 任意版本对比；
- 定时发布；
- 恢复原因和发布日志；
- 单个区块恢复。
